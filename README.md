# 丞石集團績效考核線上化系統（核心流程雛形）

Next.js 16 + TypeScript + Tailwind 打造的績效考核線上化雛形，涵蓋「自評 → 初評 → 複評 → 人資彙整 → 董事長核決」完整流程。人員／部門資料依丞石集團真實組織圖（2026/08 版本，4 間關係企業、共 96 人）建置。

## 重要說明

- **資料儲存於伺服器記憶體**，每次重新啟動或重新部署都會重置為初始狀態（所有考核表回到「待自評」）。這是雛形設計，正式上線前需要換成真正的資料庫（PostgreSQL／MySQL 皆可）。
- **沒有真正的登入驗證**，登入頁是用 cookie 模擬「切換身份」，方便展示與測試。正式上線前必須加上真實的帳號密碼或 SSO 驗證，否則任何人都能切換成任何員工的身份。
- 員工的工號（SYS-001…）與到職日是系統暫編的佔位資料，因為組織圖上沒有這些欄位；正式上線前建議串接真正的人資系統（工號、到職日、在職狀態等）。
- 排名等第（第10項）的常態分配比例（5% / 15% / 65% / 10% / 5%）與各部門人數不足4人時「不區分第一、第五等」的放寬規則，都已依原始紙本考核表的規則實作。

## 本機執行方式

需要 Node.js 18 以上版本。

```bash
npm install
npm run build
npm start -- -p 3000
```

啟動後開啟瀏覽器至 http://localhost:3000 即可使用，登入頁可選擇任一位員工的身份體驗對應流程。

開發模式（會即時反映程式碼修改）：

```bash
npm install
npm run dev
```

## 部署到 Vercel（取得可分享測試網址）

1. 到 https://vercel.com 用您的帳號登入。
2. 確認帳號有「建立新專案」的權限（若帳號隸屬某個 Team，需要該 Team 的 Owner 或 Member 且具備建立專案的角色；個人帳號通常預設就有權限）。
3. 使用 Vercel CLI 部署：

   ```bash
   npm install -g vercel
   cd 這個資料夾
   vercel
   ```

   或是把這個資料夾推到一個 GitHub repository，再到 Vercel 網站上選「Import Project」串接該 repository，之後每次 push 都會自動部署。

4. 部署完成後 Vercel 會給一組網址（例如 `https://your-project.vercel.app`），即可分享給同仁測試。

**部署前請先加上登入驗證**（見上方「重要說明」），否則任何拿到網址的人都能切換成任何員工的身份、檢視所有人的考核內容。最簡單的作法是先用 Vercel 的密碼保護功能（Project Settings → Deployment Protection）暫時擋住整個網站，僅供內部測試。

## 專案結構

```
app/                  Next.js App Router 頁面與 Server Actions
  page.tsx            首頁（依角色顯示待辦事項）
  login/               示範登入（cookie 模擬身份切換）
  form/[formId]/        考核表詳情頁（自評／初評／複評共用同一頁面，依角色顯示可編輯區塊）
  review/               「待我初評」「待我複評」清單
  hr/                    人資彙整看板、考核週期設定、CSV 匯出
  approve/               董事長核決中心（依公司別區分權限）
components/            共用元件（狀態徽章、等第選擇器、排名分佈預覽等）
lib/
  types.ts             型別定義
  store.ts             真實組織資料（4間公司、28個部門、96位人員）與記憶體資料儲存
  auth.ts              示範登入（cookie）
  permissions.ts        依表單狀態與角色關係計算可編輯／可核決權限
```

## 目前已知限制（正式上線前待補）

1. 資料庫：目前用伺服器記憶體暫存，重啟即重置。
2. 登入驗證：目前無真實帳密驗證。
3. 員工資料：工號／到職日為佔位資料，尚未串接正式人資系統。
4. 尚未實作：獎金試算、歷史考核查詢、到期提醒通知（皆為 PRD 中規劃的後續功能，本次雛形聚焦在核心流程打通）。
